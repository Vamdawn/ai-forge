# Agent-friendly CLI 检查清单

逐项检查并记录证据；`部分通过` 用于已有约定但缺字段、边界或文档不足的情况。

| # | 规则 | 证据应回答的问题 |
|---:|---|---|
| 1 | 帮助即契约 | `--help` 是否说明用途、参数类型/必填、默认值、示例、输出、退出码和副作用？ |
| 2 | 能力可发现 | 根命令能否列子命令，并提供机器可读能力/schema？ |
| 3 | 参数显式 | 是否长参数优先、区分位置参数/选项/重复参数并拒绝未知参数？ |
| 4 | stdin 可注入 | 大文本、批量记录和敏感值能否通过 stdin 或 `--file -` 注入？ |
| 5 | stdout 纯机器数据 | 机器输出模式的 stdout 是否没有提示语、颜色和进度？ |
| 6 | stderr 放诊断 | 日志、警告、进度和调试信息是否只写 stderr，并支持 quiet？ |
| 7 | 稳定退出码 | 成功、参数、认证/权限、找不到、冲突、超时、部分完成是否可区分？ |
| 8 | 可操作错误 | 错误是否含 `code`、`message`、`details`、`retryable`、`next_action`？ |
| 9 | 幂等键 | 创建/写入是否接受幂等键，重试是否不会产生重复副作用？ |
| 10 | 重试边界明确 | 是否说明可重试错误、退避建议和不可重试错误？ |
| 11 | 分页与限量 | 列表是否支持 limit/cursor，并返回 next cursor 与是否更多？ |
| 12 | 选择字段 | 是否支持 fields、jq、template 或等价投影以降低 token 成本？ |
| 13 | 确认与权限显式 | 破坏性操作是否有 dry-run/confirm/策略，且无 TTY 不会隐式放行？ |
| 14 | 凭据不进参数 | 是否支持环境变量、stdin 或凭据助手，且日志和错误脱敏？ |
| 15 | 可组合原语 | 命令能否通过 stdin/stdout 管道连接，不强制共享临时文件？ |
| 16 | 确定性与时钟 | 是否有 timeout、max-items 等边界，同样输入能产生可比较结果？ |
| 17 | 资源与副作用声明 | 帮助/schema 是否标明读写资源、网络访问、成本和副作用？ |
| 18 | 进程信号友好 | SIGTERM/SIGINT 是否产生可识别取消状态并避免未知半成品？ |
| 19 | 自检与环境探测 | 是否有 doctor 或能力探测命令返回依赖与资源状态？ |

## 推荐响应

错误示例：

```json
{"ok":false,"error":{"code":"RATE_LIMITED","message":"请求过于频繁","retryable":true,"retry_after_ms":2000,"next_action":"wait_and_retry"}}
```

列表响应至少表达 `items`、`next_cursor`、`has_more`；写操作至少表达资源 ID、是否实际变更和幂等键（若适用）。
