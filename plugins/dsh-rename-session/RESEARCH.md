# DeepSeek Harness session rename plugin research

Research date: 2026-10-13. Sources are limited to documentation and code in the [official DeepSeek repository](https://github.com/deepseek-ai/deepseek-harness).

## Version baseline

The target runtime is `0.2.0-rc.2`. Official tag `dsh-v0.2.0-rc.2` resolves to commit `639ed015397290b3745d163aafe02ffee4aa3f84`. References below are pinned to that commit unless stated otherwise. At the time of research, `master` was `0.2.1-alpha.2` at commit `d743267388641bc76f17c45ce8b4c231aed1d32c`. Newer model-call preparation and title-provider helpers require compatibility checks before use with rc.2.

## Official development guides

- [Your first plugin](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/docs/user/develop/basic/index.zh.md): export `apply(ctx)`, declare dependencies through `inject`, and use `ctx.effect()` for unload cleanup.

- [Adding a Remote API](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/docs/cookbook/adding-a-remote-api.zh.md): covers host services, method descriptors, client mounting, and failure results.

## Session "..." menu

The extension point is `sidebar.workspaces.session.menu.item`. Register through `ctx.slots.inject(slot, () => ctx.slots.register(metadata, Component))`. The component receives `sessionId`, `displayTitle`, and `useMenuOpenState`; call `setMenuOpen(false)` on selection. Built-in Rename has order 200 and Fork has order 300, so this plugin uses 250 with a distinct contribution ID. Use the runtime's `MenuItemButton` and the same `IconEditOutlineRegular` component as built-in Rename.

Sources: [Workspace slot documentation and example](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/ui-workspace/README.zh.md#%E6%89%A9%E5%B1%95-session-%E8%A1%8C%E6%93%8D%E4%BD%9C), [browser plugin fixture](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/apps/web/tests/fixtures/plugins/fixture-live-client/client.js), [official menu end-to-end test](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/apps/web/tests/client-plugin-live.e2e.ts).

Closing the menu unmounts its component. Generation state, errors, and cancellation must therefore live in persistent plugin state or `shell.overlay`. The official manual rename dialog also lives outside the menu. Source: [RenameSession.tsx](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/ui-workspace/src/client/session-actions/RenameSession.tsx).

## Session access and context

- Use `ctx.sessions.using(sessionId, { source: 'workspaceOperation' }, callback)` on the client. It waits for initial history opening and releases the reference after callback success or failure. Official Rename follows this path. Sources: [rename invocation](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/ui-workspace/src/client/index.ts#L161), [using implementation](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/api/session-controller/src/client/sessions/service.ts#L297).
- Host Agent/Session Remote lookups only return active objects; they do not resume cold sessions. Make the auxiliary request after client session acquisition completes. Sources: [Agent lookup](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/core/agent/src/index.ts#L258), [Session lookup](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/core/session/src/index.ts#L955).
- `session.deriveMessages()` snapshots the current model history, including projections and compacted messages. Nodes replaced by compaction are absent from the result. Describe this as the current context rather than all original historical text. Source: [deriveMessages](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/core/session/src/index.ts#L842).
- Read the model route from `session.requestHeader().config.provider/model`. The header may be absent before the first model request, so a route cannot be assumed. Sources: [requestHeader](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/core/session/src/index.ts#L788), [official auxiliary route check](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/experimental/auto-review/src/index.ts#L365).

## Model generation and persistent renaming

In rc.2, call `ctx.llm.stream({ provider, model, system, messages, maxTokens, signal, sessionId, purpose: 'session-title' })` and assemble the response with `BlockAssembler`. The auxiliary request reuses the Harness model and credentials without a separate DeepSeek HTTP client. Serialize user and assistant context into one text message and instruct the model to output a concise title. The request does not send a new prompt to the main conversation or execute tools. Bound input size, output tokens, and duration, and validate the terminal finish reason and nonempty text before writing.

Sources: [GenerateOptions](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/llm/src/types.ts#L511), [official title request](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/session/session-title-llm/src/index.ts#L260), [auxiliary request example](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/experimental/auto-review/src/index.ts#L627).

Runtime testing found skill catalogs and environment snapshots among `user`-role messages. Filter `source.form` values `instructions`, `catalog`, and `snapshot` while retaining conversation text and compaction summaries to keep title generation focused on the topic. Sources: [message source semantics](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/llm/src/message.ts#L62), [skill catalog source](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/skill/tool-skill/src/index.ts#L33), [compaction checkpoint source](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/compaction/compaction/src/checkpoint.ts#L19).

Persist through `ctx.sessionTitle.rename(session, title)`. It returns a normalized `SessionTitleSnapshot` and appends a `session/title` event whose source is `user`. An explicit user-triggered rename pins the title against subsequent automatic generation. The service owns control-character cleanup, UTF-8-safe length limits, and title projection. Sources: [title service](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/session/session-title/README.zh.md), [official rename command](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/api/session-controller/src/commands.ts#L193).

`sessionTitle.refresh()` uses the existing generation strategy. The service permits only one title provider, and the built-in provider mainly reads human messages. An independent request can include assistant context without replacing the default automatic naming strategy. Source: [title provider constraints](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/session/session-title/README.zh.md).

## Client-host calls and package structure

The package includes host and client entry points, `package.json`, and `cordis.patch.yml`. The client menu sends only the session identity. Gateway Remote is one public option: `ctx.typert.register(contribution)` on the host and `ctx.remote.$mount(contribution)` on the client use method descriptors and schemas. TypeScript packages can use `TypertRemoteService`, `@Remote`, and generated `./typert` and `./remote` artifacts.

Sources: [RPC development workflow](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/docs/cookbook/adding-a-remote-api.zh.md), [Typert register](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/typert/registry/README.zh.md), [client mount](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/api/gateway/src/client/index.ts#L202).

This plugin uses the public `ctx.connection.fetch.register` API to register a POST handler at `/api/dsh-rename-session`. The browser uses the document-relative path `api/dsh-rename-session`. The route inherits Connection's Host/Origin checks and browser authentication, validates `{ sessionId }`, and returns JSON without generated Typert artifacts. Official session-log export uses the same Fetch mechanism. An independent `rpc.handle` channel triggered an internal `webServer` injection error in the installed rc.2 runtime and was not used.

Sources: [public Fetch contract](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/connection/src/rpc.ts#L140), [authenticated shared route](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/connection/src/index.ts#L149), [official export implementation](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/session-query/session-log-export/src/index.ts), [path conventions](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/session-query/session-log-export/src/routes.ts).

The browser bundle registers through `window.__ModuleLoader__.load({ id: packageName, factory(require) { ... } })`. React, Cordis, and static UI libraries come from the loader's shared platform and must not be bundled again. `dsh.client.external` declares only requests beyond that platform. Source: [client module protocol](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/modules/README.zh.md#%E5%85%B1%E4%BA%AB%E6%A8%A1%E5%9D%97%E8%A1%A8).

## Installation and validation

Officially shipped locales are Chinese (`zh`) and English (`en`); rc.2 and the researched master revision both declare these in `LOCALE_IDS`. Language packs can call `addLanguage` and declare a fallback chain ending at `en`. Register complete plugin dictionaries through `locale.register(ns, { zh, en })`. Slot-provided `t` triggers updated rendering after language changes, so store stable error codes and translate them during rendering rather than storing fixed-language error sentences.

Sources: [official locale IDs](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/locale/src/locale-settings.ts#L15), [language switching and extensions](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/locale/README.zh.md), [master locale IDs](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/locale/src/locale-settings.ts#L15).

Install locally with `dsh plugin --profile web add ./plugins/dsh-rename-session`, inspect with `dsh --profile web --dump-config`, and start with `dsh web`. The CLI requires pnpm on PATH. Linked directories retain their own `node_modules`; peer dependencies let shared Harness packages use the host instance. Sources: [installation guide](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/docs/user/develop/basic/publish.zh.md), [CLI reference](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/apps/cli/reference/README.zh.md#%E6%8F%92%E4%BB%B6%E7%AE%A1%E7%90%86).

Validation should cover menu ordering and closure, warm and cold session access, context input, preservation of existing titles when routes or history are unavailable or generation fails or is cancelled, durable title updates, and cleanup on unload. Use an isolated `DSH_HOME` and deterministic model stub, then exercise the actual menu to verify client-host assembly. The official [client-plugin-live.e2e.ts](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/apps/web/tests/client-plugin-live.e2e.ts) demonstrates real profile, Remote, bundle, and slot verification.

See [README.md](README.md#development-and-validation) for this implementation's validation results and commands. The plugin uses an authenticated Fetch route, so runtime assembly validation covers the client-host HTTP path.

## TypeScript authoring

Implementation: this plugin now uses `src/index.ts`, `src/client.tsx`, shared protocol types, and typed bilingual dictionaries. Separate strict Host and Client checks prevent their service declarations from mixing. A self-contained esbuild configuration emits ESM `dist/index.js` and the required lazy-CJS `dist/client.js`, keeping runtime packages external. The manifest exports these compiled artifacts; tests exercise them, and installation into the local Desktop profile was validated through a real smoke-test rename. See [development and validation](README.md#development-and-validation).

- **TypeScript is officially supported.** The first-plugin tutorial defines a plugin as a TypeScript module exporting `apply(ctx: Context)` and loads an absolute `.ts` path from an overlay. React UI components can use TSX, as the built-in Rename component does. Sources: [first plugin](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/docs/user/develop/basic/index.md), [RenameSession.tsx](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/ui-workspace/src/client/session-actions/RenameSession.tsx).
- **Source execution and installed Desktop have different requirements.** Repository `pnpm dsh` starts Node with `--import tsx/esm`, enabling Host TypeScript source imports. Packaged Desktop runs compiled JavaScript and pre-generated Typert metadata; it does not compile TypeScript plugins. A plugin linked into the installed Desktop must therefore provide built JavaScript entry points. Sources: [source execution](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/apps/cli/reference/README.md#source-execution), [rc.2 Desktop runtime file selection](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/apps/desktop/README.md#runtime-file-selection).
- **The browser always consumes a built bundle.** Declare `dsh.client.platform: "web"`, export the built `./client` artifact, and emit the lazy-CJS registration protocol `window.__ModuleLoader__.load({ id, factory })`. Even source launches consume built client exports. Keep React, Cordis, and the static UI libraries external to preserve shared runtime instances. Sources: [client build requirements and shared modules](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/modules/README.md#use-this-package), [official bundle preset](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/tsdown.client.ts).
- **The official `clientBundle` helper is repository-local.** Official UI packages import `../tsdown.client.ts`, and the helper itself imports repository scripts and workspace paths. An independent plugin needs a self-contained build configuration producing the same runtime artifacts, rather than assuming this helper is an installed SDK export. Sources: [workspace build configuration](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-workspace/tsdown.config.ts), [preset dependencies](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/tsdown.client.ts).
- **Distribute compiled artifacts or build during Git installation.** npm packages and tarballs should contain the compiled entry points. For Git installation, provide a self-contained `prepare` script; pnpm 10+ requires the user to allowlist that package's build before it executes. Shared Harness dependencies belong in both `peerDependencies` and `devDependencies` so development gets types while runtime uses the host's instances. Source: [packaging and Git installation](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/docs/user/develop/basic/publish.md).
