# Noticeflow 变更记录

[English](CHANGELOG.md) | 简体中文

## [Unreleased]

### Added

- 新增通过 `server.publicBaseUrl` 配置的子路径部署，覆盖 MCP/OAuth 发现、登录跳转、Cookie 及令牌资源标识。现有根路径部署地址保持不变，Noticeflow 可与 HTTPS 站点共用域名而不接管其根路由。
- 新增实验性 Node.js 24 服务端，包含 OAuth/CIMD、通知 MCP 工具、加密 SQLite 扇出、受配额约束的投递、停服密码重置、备份恢复命令及 Docker 构建。本地公共边界自动化测试覆盖协议、授权、投递和恢复行为；真实 Host 及企业微信仍待部署验收。
- 在实现前确定以服务端为交付主体的初版 MCP 产品边界及通知领域模型；现成 Host 使用自己的 MCP Client 接入。
- 补充鉴权、持久投递、加密存储、运维与验收的初版技术方案，为后续实现提供具体依据。
- 补充架构审查，指出实施前需处理的 OAuth 回调、数据库恢复及投递调度缺口，并提供一方资料和验收用例。

### Changed

- 在现有服务端包内拆分授权持久化与离线恢复职责，并集中维护 OAuth 契约，配置、端点及存储格式保持不变。停服时先通过 handler 结束活跃 MCP 订阅，再释放存储。
- 验证 Codex CLI 0.155.1 通过本地 HTTPS 完成 OAuth、真实 Agent 提交及自动令牌刷新。验收启动脚本保持 Worker 禁用，两条通知均留在队列中且投递尝试为零；公网入口及真实渠道仍未验收。
- 验证 Linux/arm64 Docker 镜像可构建、以非 root 用户启动、通过运行时配置的健康检查，并在删除初始密码配置后使用原数据库重启。其他镜像平台、公网入口及其余 Host/渠道接入仍未验收。

- 对齐产品与技术方案中的重试计数、任务时间筛选、日志字段、按 Client 限流及刷新令牌滚动有效期，使实现遵循同一契约。

### Fixed

- 在登录表单的安全策略中允许经 OAuth 校验的回调来源，使 Chromium 能在同意授权后返回 MCP Host，修复页面停留及再次提交后失败的问题。
- 为白名单内的 CIMD 文档获取提供最长十秒的等待时间，使延迟较高的出站代理也能完成 OAuth 登录。请求仍有超时边界，并保留鉴权库的 SSRF 防护及元数据校验。
- 接受同时列出 loopback IP 和 `localhost` 回调的官方 Codex 原生 CIMD 文档，仍严格校验 Client ID 白名单及回调主机、路径。此前这类文档会在登录前被拒绝。
- 修正原生 OAuth loopback 回调及保全 WAL 的 SQLite 排他恢复设计，为 Claude Code 默认登录和中断恢复明确验收规则。
- 通过保守配额预留和持久化目的地共享冷却修正投递调度设计，使延迟发送及重试在重启前后遵守同一限额。
- 补齐刷新令牌签发及 Grant 滚动续期设计，并要求停服后持排他锁重置密码，避免进行中的请求写回旧授权。
- 将 Webhook 快照、发送、配额及冷却统一到经过验证的规范化目的地，避免等价 URL 写法产生独立限额。
- 明确按份数保留备份及运维清理恢复副本的规则，并将各文档统一为两个目标 Host 均须验收，不将文档修订视为实现验证。
