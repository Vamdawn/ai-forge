# Noticeflow 变更记录

[English](CHANGELOG.md) | 简体中文

## [Unreleased]

### Added

- 新增实验性 Node.js 24 服务端，包含 OAuth/CIMD、通知 MCP 工具、加密 SQLite 扇出、受配额约束的投递、停服密码重置、备份恢复命令及 Docker 构建。本地公共边界自动化测试覆盖协议、授权、投递和恢复行为；真实 Host、企业微信及镜像运行仍待部署验收。
- 在实现前确定以服务端为交付主体的初版 MCP 产品边界及通知领域模型；现成 Host 使用自己的 MCP Client 接入。
- 补充鉴权、持久投递、加密存储、运维与验收的初版技术方案，为后续实现提供具体依据。
- 补充架构审查，指出实施前需处理的 OAuth 回调、数据库恢复及投递调度缺口，并提供一方资料和验收用例。

### Changed

- 对齐产品与技术方案中的重试计数、任务时间筛选、日志字段、按 Client 限流及刷新令牌滚动有效期，使实现遵循同一契约。

### Fixed

- 修正原生 OAuth loopback 回调及保全 WAL 的 SQLite 排他恢复设计，为 Claude Code 默认登录和中断恢复明确验收规则。
- 通过保守配额预留和持久化目的地共享冷却修正投递调度设计，使延迟发送及重试在重启前后遵守同一限额。
- 补齐刷新令牌签发及 Grant 滚动续期设计，并要求停服后持排他锁重置密码，避免进行中的请求写回旧授权。
- 将 Webhook 快照、发送、配额及冷却统一到经过验证的规范化目的地，避免等价 URL 写法产生独立限额。
- 明确按份数保留备份及运维清理恢复副本的规则，并将各文档统一为两个目标 Host 均须验收，不将文档修订视为实现验证。
